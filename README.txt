BEFORE PUBLISHING (IMPORTANT)
1. The Email Monik button opens a pre-addressed Gmail compose window for monikwadhwani21@gmail.com (professional email for IIMB, academic and collaboration-related messages). It opens in a new tab; the visitor needs to be signed in to Gmail to send from Gmail. The displayed email address beside the button is also a backup link to the device's default email app.
2. Check every personal detail before publishing. The site deliberately does not list certificates or awards taken from another person's portfolio. Add only certificates that you can verify are yours (exact title, issuer and date).
3. The WORK IN PROGRESS visual now includes an original hard-hat builder/miner illustration, pickaxe, site markings, a construction label, and a small animated build-status indicator. The footer also has a mini construction status board.
4. The site uses Google Fonts (DM Sans, DM Mono and Instrument Serif). If the viewer has no internet connection, fallback fonts are used automatically.

HOW THE FILES WORK
- HTML uses semantic elements such as header, nav, main, section, article and footer.
- The CSS uses element selectors, class selectors, ID-linked sections, pseudo-classes, CSS variables, Flexbox, CSS Grid, positioning, responsive media queries and a reduced-motion preference.
- There is no JavaScript framework or external component library. The website is a static HTML/CSS page and works on GitHub Pages.

PUBLISH TO YOUR EXISTING GITHUB REPOSITORY
1. Download and unzip this folder on a computer.
2. Open your existing resume-website repository on GitHub.
3. Keep the repository name and its existing branch. Upload index.html and style.css to the same folder from which your current GitHub Pages site is published (usually the repository root).
4. If GitHub asks whether to replace index.html or style.css, replace the old versions only after keeping a backup copy locally.
5. Commit the changes to the same branch used by GitHub Pages.
6. In the repository, open Settings > Pages. Confirm the Source is Deploy from a branch and the selected branch/folder is the one containing index.html. Save if you changed it.
7. Wait for the Pages deployment to finish. Open the live site using the Visit site link under Settings > Pages.
8. Test the live site on a computer and phone. Click each navigation link and the email button.

IF YOUR SITE USES A /docs FOLDER
Upload both files inside /docs only if Settings > Pages says the publishing folder is /docs. Do not put index.html in a different folder from the one GitHub Pages publishes.
